PART A · 本地 AI 代理 openai-proxy — 把 TeleAgent 变成标准 OpenAI 接口
壹
是什么
一个 1800 行的 Python 代理
🔌

标准 OpenAI 兼容接口

将 TeleAgent 桌面应用的 super-agent API 转换为标准 /v1/chat/completions 和 /v1/models 端点。任何支持 OpenAI API 的工具/SDK（Cursor、ChatBox、LangChain…）无需改代码即可接入。

⚡

零依赖 · 纯 Python

纯标准库实现（http.server + hmac + threading），无任何 pip install。线程安全、SSE 流式输出、自动签名认证，启动即用。监听 0.0.0.0:8088，局域网可访问。

接入方式
三行代码即可调用
# Python OpenAI SDK 接入
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8088/v1", api_key="any") # api_key 随意填
resp = client.chat.completions.create(
    model="NewApi/chat-pro",
    messages=[{"role": "user", "content": "帮我配餐"}]
)
print(resp.choices[0].message.content)

为什么要融合
1+1 > 2

单独的 openai-proxy

  • 能力很强，但只是一个本地 API 接口
  • 需要自己写代码 / 配工具才能调用
  • 缺少触达一线员工的最后一公里
  • 适合开发者自用，不适合全员推广

单独的 wecom-bot

  • 能触达群聊，但缺少 AI 能力时只是消息转发器
  • 如果直连外部大模型 API，需重复管理密钥/模型/计费
  • 无法复用 TeleAgent 的工具链和技能体系
  • 看图、配餐、质检等复杂能力难以独立实现

融合之后 —— 完整闭环

  • openai-proxy 提供 AI 能力：标准接口 + 自动签名 + 会话管理 + 模型切换，无需维护额外密钥
  • wecom-bot 提供触达通道：企微 + QQ 双通道，@即用，一线员工零门槛
  • TeleAgent 提供智能内核：看图工具 + 河南标准化技能 + 长期记忆 + 多智能体
  • 三者串联：群聊 @ → 消息管线 → 8088 代理 → AI 大脑 → 回复 + 台账 + 待办，全自动闭环

1营业厅群智能配餐

客户在企微群发账单截图 @机器人 → AI 看图识别套餐与消费 → 按五步法给出提值方案 → 自动写台账 + 建待办 → 群里通知含链接。

群聊 @ → server.py 接收 → 8088 代理 → TeleAgent 看图+配餐 → 回复+台账+待办

2质检话术即问即答

营销人员在 QQ 群 @机器人 提问：录音质检要点、五步法话术、比算单填法、FTTR 推荐，AI 基于河南标准化技能即时回复，培训即用。

QQ @ → botpy 接收 → 8088 代理 → TeleAgent 加载技能 → Markdown 回复

3日报通报自动推送

定时任务调用 push.py：收入日报、质检通报、AI 新闻等 Markdown 图文自动推送到企微群 / QQ 群，无需人工复制粘贴。

定时脚本 → push.py → 企微 Webhook / QQ post_message → 群聊收到通报

4Cursor / ChatBox 接入 AI

开发时用 Cursor / ChatBox / LangChain 直接连 8088 代理，复用 TeleAgent 的模型与技能能力，写代码、查文档、做分析一站搞定。

Cursor / SDK → http://127.0.0.1:8088/v1 → 代理签名转发 → TeleAgent AI 回复
